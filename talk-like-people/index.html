Teaching a small model to talk like people

Chatbots get tested against fake users, and the fake users are too polite. humans& trained a 550B model to imitate people instead. I rebuilt the recipe on a 0.6B model and free GPUs to see which parts hold up.

Why imitate people?

Before a chatbot ships, it gets tested on conversations. Real users are slow and expensive to recruit, so another model usually plays the user. Usually that model is an assistant told to act like one.

That makes the test too easy. Assistants are trained to be clear, helpful and agreeable. People are terse, make typos, change the subject, and leave when they are annoyed. When researchers ran 451 real people through the same agent tasks as 31 simulated users, the simulated ones were too cooperative and too uniform, and agents scored better against them than against people.

humans& built Persimmon to play the people instead of the assistant, including group chats with several people at once. Their write-up describes the training in a few sentences and shares no code. I wanted to know how much of it works on a model about 900 times smaller, trained on Kaggle’s free GPUs.

What does “talk like people” mean?

A good assistant gives the best reply. A good simulated user gives a typical one, and over many conversations it gives every kind of reply about as often as people do. humans& call this matching the distribution.

Ask a group chat how its weekend was.

People answer “good”, “meh”, “worked all weekend ugh”, a photo, or nothing at all. A model that always gives the single most likely answer looks fine one message at a time and is wrong as a whole. A model that matches people gives each kind of answer about as often as they do.

So the test can’t be a score for one reply. It is a Turing test over many. A judge sees the start of a real conversation, then two versions of the next four messages: what people actually wrote, and what the model wrote. It picks the real one. The fooled rate is how often it picks the model instead. At 50% the judge can’t tell them apart. At 0% it always can.

Four judges show up below. One is used during training. The other three only grade.

The classifier learns from a few hundred examples, so it picks up statistics such as length and word choice. The language models read the conversation the way a person would. Their fooled rates sit on different scales, so I only compare models under the same judge.

The recipe

Persimmon starts from a model that has not been taught to be an assistant, trains it on conversations between people, then trains it further against a judge. Here is the same shape at small scale.

A bug that hid everything

The first version wrote each message between the model’s chat markers, <|im_start|> and <|im_end|>. Every message the model wrote failed the same way: it never ended. None of 99 test samples was usable, so the judge-training step had nothing to learn from.

Those markers are in the base model’s vocabulary, but it was never trained on them. Each word in a model is stored as a list of numbers, and these two lists were about a third as long as normal ones, pointing almost exactly at the average of all the others. The model could read them but could almost never write them, and the cheap fine-tuning I used can’t change them.

Asked to continue a chat in the old format

 ⚐薄弱
 ⚐薄弱
 ⚐薄弱
 ⚐薄弱

The same model, asked to continue “The capital of France is”

 Paris. The capital of Germany is Berlin

Both come from always picking the single likeliest next word. The model was fine. The markers were not.

The fix was a format the base model has seen many times: a plain chat log, one message per line.

What the model reads, shortened

## Setting
Ubuntu community IRC channel #xubuntu on 2015-04-28. Public text chat where people drop in to ask for and offer technical help.
## Participants
- nina
- tomas
- kai
## Chat log
<tomas> the screen goes black but the power button is still blue
<nina> tomas: maybe it's still plugged in?
<tomas> nina: i've tried without AC

A message now ends at a line break, which every model predicts well. With no training at all, the base model wrote 7 usable continuations out of 8. Because each line starts with a name, the model also decides who speaks next. That gets its own section.

Training against a judge

Step 2 only ever shows the model real conversations. When it writes four messages on its own, each one becomes the context for the next, so small mistakes pile up. humans& say their judge-training step is what made long conversations hold together.

Here is how that step works. The model writes eight versions of the next four messages. The judge scores each one. The model shifts toward the versions that scored better than their siblings. A penalty keeps it close to the step 2 model, so it can’t wander far just to please the judge.

Why a judge, and why one that keeps changing?

Nobody can write down what people would say next. A classifier can still learn to tell real from fake, and how confident it is says how far the model is from people. As the model improves, an old judge stops being able to tell. So it is retrained on the model’s newest messages, and the target moves with the model.

The first try made the model worse. The training judge was weak, right only 55–67% of the time, and the model found a shortcut: shorter messages give a weak judge less to go on. Half of its messages became 31 characters or shorter. For people, and for the model before this step, that midpoint was about 42. The training judge stopped being able to tell real from fake. The classifier judge, which the model had never seen, caught it: the fooled rate fell from 40% to 30%.

People say hello, then someone asks a real question and gets a long answer. The gamed model writes only fragments.

That is why the final judge has to be a different one. A model graded by the judge it trained against gets credit for fooling that judge in particular.

The next run changed several things. The two that matter most for this story: train the judge until it is right at least 70% of the time on held-out conversations before training against it starts, and watch message length. If length drifts more than 25% from people’s, stop and go back to the last good checkpoint.

This time step 3 helped under both judges. Table 2 shows it didn’t get there by changing one habit. Naming the person you reply to rose to 38%, against people’s 37%, and made-up speakers fell to 3%. Messages were still a little short.

Now tomas answers kai’s question, kai follows up, and the thread keeps going. One detail, a “64-bit seahorse”, is something no person would write. This is one example, picked because it is short.

What gpt-oss-120b said about this pair

“kai is probing if encryption [is] present. So a plausible response: ‘i don’t think so.’ … ‘it’s 64-bit seahorse’ is nonsense (64-bit seahorse? Seahorse is [a] key manager). That’s weird. Also kai says ‘oo’ … earlier they were discussing hibernation issues, not a USB drive. So B seems off.” It picked the real messages.

The judge is right, and a little unfair. Seahorse is the name of Ubuntu’s app for passwords and encryption keys, so even the odd detail came from the topic at hand.

Where does it help?

If step 3 fixes the way mistakes pile up, its edge should grow with each message the model writes. In a later run, the model wrote eight messages, and the judge looked at the first one, the first two, the first four, and all eight.

That is the pattern humans& describe: training against a judge helped long conversations, not single replies. Another run showed the same thing on eight-message windows, under both judges: 33% against 12% with the classifier judge, and 25% against 17% with Phi-4.

Who talks next?

In a group chat the model has to decide who speaks, not only what they say. How it does that comes down to the format. Each message is a line that starts with a name, so for every message the model first writes who is speaking, then what they say, then a line break. All three are part of the same training target. Nothing tells the model whose turn it is. It learns that from who actually spoke next in real chats.

A few choices shape what it can learn.

Everyone is listed. The header names everyone in the conversation, including people who haven’t spoken yet in the excerpt, so newcomers can join. In the laptop thread, dee did.

Habits stay in. Sending two messages in a row, fixing a typo in the next one (“poser/power”), naming the person you answer: the data keeps all of them.

The model picks every speaker. It can be made to speak as a particular person by writing their name first, but none of the tests do that.

Timing is gone, at first. The logs have timestamps, but the main runs dropped them, so the model couldn’t know who paused, for how long, or who was typing at the same time. The experiment below puts time back.

Turn-taking is where the small model is furthest from people. When someone is named, they answer next 59% of the time in real chats, and 42–50% of the time for the models. The models also send two messages in a row more often than people do.

wes: you're welcome :)
wes: :-)

The model has wes thank cal, then answer his own thank-you. No person does that. gpt-oss-120b still picked it as the real one. The real people had jumped to a new topic, a release party, and the judge reasoned that real chat would keep joking about the wrong-channel message. People change the subject. Judges, like simulators, expect them not to.

Can it be taught?

I tried one run aimed only at turn-taking, with two changes to step 2. Each message now records the minutes since the previous one: <kai> [+3m] do you use disk encryption?. The time comes after the name, so the model decides who speaks before it sees how long they waited. And the loss counts the name three times as much as the rest of the message, so the who-decision gets more of the training signal. A control model got the same data and training without either change. The logs have no join or leave lines, so time is the only cue about who is around that I could add back.

Two tests tell different stories.

Knowing who should talk. Show the model the real conversation and ask how likely each participant is to speak next. The changed model puts the real next speaker first 58% of the time, against 53% for the control and 50% before any training. Scored on the same 285 conversations, that gap is unlikely to be luck (p = 0.04). It is still modest: when someone was just named, the model only matches the simple rule “the named person answers”, 57% against 58%.

Doing it. Writing on its own, the changed model takes turns no better than the control. The person named replies next 46% of the time (control 49%, people 59%), and the same person sends two in a row 42% of the time in both (people 33%). The reason is visible in the numbers. Shown the real conversation, the model gives “the same person again” 38%, close to the real 35%. Writing freely, each of its messages becomes the context for the next, and a small lean compounds into a large one.

Two cheaper fixes did less. Letting a line start only with someone already in the chat removed made-up speakers entirely (3% to 0%), but nothing else moved. Step 3, the judge training, was the only change that pulled free-running turn-taking toward people: back-to-back messages fell from 42% to 38%, and the number of people speaking in four messages rose from 2.10 to 2.20 (people: 2.29). It also shortened messages again, until the length check stopped it and went back to an earlier checkpoint.

So the gap is not in what the model knows. It is in what happens when it writes on its own, which is exactly what step 3 trains. The next experiments put turn-taking into step 3’s reward, and adjust how each speaker is chosen when the model writes.

What I’d keep

  1. Start from a model that was never taught to be an assistant, and give it a format it already knows.

    The untrained base model wrote usable group chat once the format was a plain log. Chat markers it had never learned to write produced nothing usable at all.

  2. Training on real conversations gets the voice.

    Message length, naming people and staying with the people in the thread all moved close to people’s.

  3. A judge is only worth training against if it is good, and only if a different judge checks the result.

    A weak judge got fooled by shorter messages. A new judge caught it, and so did simply watching message length.

  4. With a good judge, it helps where mistakes pile up.

    The gain showed from the fourth message on, the same pattern humans& report.

  5. Turn-taking is the hardest part.

    Timing and a heavier weight on names taught the model who should speak next. Writing freely, it still lets the named person answer less often than people do and sends two messages in a row more often. Only step 3 moved that.

The limits are large. This is a 0.6B model trained on one kind of conversation: technical help on Ubuntu IRC, mostly from the 2010s. The test sets are a few hundred conversations, so a gap of a few points is noise, and fooled rates for the same model moved between runs. Persimmon is 550B, trained on far more varied conversations and judged on eight-message group chats. None of these numbers can be set against its 19.8%.

Two open models are worth knowing about: UserLM-8B from Microsoft, trained on people’s messages to ChatGPT, and OSim-8B from CMU, trained across many kinds of human behavior. Neither is built for group chat. A companion note asks what a simulated student knows.
